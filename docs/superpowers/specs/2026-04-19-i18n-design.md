# i18n / Multilanguage — Design Spec

**Datum:** 2026-04-19  
**Status:** Approved  
**Settings-Version:** 1.4.0

---

## Ziel

Die gesamte Benutzeroberfläche (Frontend, Electron Tray + Startup-Fenster) wird internationalisiert. Zum Start: Deutsch (primär) + Englisch. Weitere Sprachen können durch Hinzufügen einer JSON-Datei ergänzt werden — kein Code-Change erforderlich.

---

## Scope

| Bereich | Abgedeckt | Anmerkung |
|---|---|---|
| Frontend (React) | ✅ | Alle UI-Strings in ~30 Komponenten |
| Electron Tray-Menü | ✅ | Einträge werden nach Sprachänderung neu gebaut |
| Electron Startup-Fenster | ✅ | `startup.html` via i18next im Main-Prozess |
| Backend | ✅ (indirekt) | Backend sendet Fehlercodes, Frontend übersetzt |

Backend bleibt sprachlos — es sendet strukturierte Status-Codes (`caps_disabled`, `connection_error` usw.), die im Frontend übersetzt werden. Das hält das Backend stateless.

---

## Library

**react-i18next** + **i18next** + **i18next-browser-languagedetector**

- `react-i18next` — `useTranslation()` Hook für alle React-Komponenten
- `i18next` — Core, läuft auch im Electron Main-Prozess (Node.js)
- `i18next-browser-languagedetector` — Auto-Detect aus localStorage / `navigator.language`

## Locale-Dateien

```
packages/shared/locales/
  de.json     ← Primärsprache / Referenz
  en.json     ← Englisch
```

In `@cwp/shared` — so importieren Frontend und Electron denselben String-Pool ohne Duplikation. Weitere Sprachen: neue Datei anlegen (z.B. `it.json`), wird automatisch erkannt.

## Spracherkennung

### Prioritätsreihenfolge (Frontend)

```
1. localStorage['cwp-language']        ← per-Gerät Override (höchste Priorität)
2. Settings.json → language            ← globaler Default für alle Clients
3. navigator.language                  ← Browser/OS Auto-Detect
4. Fallback: 'de'
```

Der Settings-Wert wird **vor** `i18n.init()` aus den geladenen App-Settings in localStorage geschrieben, damit die normale i18next Detection-Order ohne Custom-Plugin greift.

### Electron (Main-Prozess)

Sprache wird aus `settingsHelper.loadSettings()` gelesen → `initElectronI18n(lang)` vor dem Tray-Aufbau aufgerufen.

## Frontend-Initialisierung

**`packages/frontend/src/main.tsx`** — vor dem React-Root-Render:

i18n wird **synchron** mit LanguageDetector initialisiert (localStorage + navigator). Die Settings-Sprache kommt asynchron über `useSettings` — sobald die Settings geladen sind, ruft der Store `i18n.changeLanguage(settings.language)` auf, falls noch kein per-Gerät Override in localStorage gesetzt ist.

```ts
// main.tsx — synchrone Basis-Init
i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: { de: { translation: de }, en: { translation: en } },
    detection: {
      order: ['localStorage', 'navigator'],
      caches: ['localStorage'],
      lookupLocalStorage: 'cwp-language',
    },
    fallbackLng: 'de',
    interpolation: { escapeValue: false },
  })

// useSettings.ts — nach Settings-Load
if (settings.language && !localStorage.getItem('cwp-language')) {
  i18n.changeLanguage(settings.language)
}
```

Neue Locale-Dateien werden in der `resources`-Map ergänzt und automatisch im Dropdown sichtbar.

## Electron-Integration

**`packages/electron/src/i18n.ts`** — neue Datei:

```ts
import i18next from 'i18next'
import de from '@cwp/shared/locales/de.json'
import en from '@cwp/shared/locales/en.json'

export async function initElectronI18n(lang: string) {
  await i18next.init({
    lng: lang,
    resources: { de: { translation: de }, en: { translation: en } },
    fallbackLng: 'de',
  })
}

export const t = (key: string, options?: object) => i18next.t(key, options)
```

- `tray.ts`: Menu-Items via `t('tray.openPanel')` etc. — Menü wird nach Sprachänderung via `tray.setContextMenu(buildMenu())` neu gebaut
- `startupWindow.ts`: Strings via IPC oder direkt in `startup.html` als Template-Ersetzung

## Sprach-Dropdown in der Toolbar

- Position: Toolbar rechts, neben ZoomControl
- Zeigt Flagge + Sprachcode: `🌐 DE ▾`
- Dropdown-Einträge: alle verfügbaren Locales mit Häkchen bei aktiver Sprache
- Klick → `i18n.changeLanguage(code)` + `localStorage.setItem('cwp-language', code)`
- Optional: "Für alle Geräte" → schreibt `language` in Settings.json via PATCH `/api/settings`
- **Wird nur angezeigt wenn mehr als eine Locale-Datei vorhanden ist**

## Nicht im Scope

- Pluralisierungsregeln (keine Strings im Projekt die Plural brauchen)
- RTL-Sprachen (kein Layout-Umbau geplant)
- Automatische Übersetzung via API
- Backend-Fehlertext-Lokalisierung über i18next im Backend (bleibt Code-basiert im Frontend)
